# Evolution — Receipts Ledger for the AI / Fleet Authoring Position

**This file is the heart of the package.** The position will adapt over time; this ledger is how the adaptation stays honest.

## The standing rule

**No silent edits.**

1. Every change to the position is a **new version** of `POSITION.md` (semver: v0.x.y draft; v1.0.0 adopted/issued; major increments on direction change).
2. Every change gets a **dated entry in this ledger**: date · version · what changed · authorised by · evidence (file + SHA-256, **including the SHA-256 of the POSITION.md version the entry produces**, review path, attack numbers). **An entry that supersedes an earlier entry or a POSITION version pins the superseded text by SHA-256 in the entry itself** — per-version hash-pinning in superseding entries is a standing rule, not a courtesy. *(Amended 2026-11-14 under E-009 — the original text read "evidence (file + SHA-256, review path, attack numbers)"; amended again 2026-11-14 under E-010 to add the superseded-version pin — the E-009 wording is preserved in E-010 per rule 4.)*
3. The **superseded text is quoted or hashed** in the entry, so the old position remains recoverable after it stops being current.
4. **Corrections are appended, never rewritten.** An error in an earlier entry is fixed by a later dated entry that says so — the earlier entry stands.
5. A change without a ruling and gate evidence recorded here has not happened, whatever any single file says.

**What this ledger claims — discipline plus detectability, not immutability.** This ledger does **not** claim that git history, or any store it lives in, is immutable: an administrator can rewrite history, and a ledger cannot attest a history it lives inside. The claim is narrower and achievable. *Discipline:* changes are made only as appended, dated, ruled entries under the rule above — no silent edits. *Detectability:* entries pin the files they touch by SHA-256, so any rewrite of this ledger or of a pinned file diverges from the hashes recorded in the entries and from the external anchor below. *(Framing corrected 2026-11-14 under E-010, gate attack 1734.)*

**External anchor.** At each POSITION version, this ledger's head SHA-256 is lodged in the HUMMBL estate record **outside this repository** — the estate daily log entry for the version's date. A rewrite confined to this repository cannot rewrite the anchor. First anchor instance: the head of this ledger as folded under E-010 (2026-11-14), recorded in the estate daily log `memory/2026-11-14.md`.
