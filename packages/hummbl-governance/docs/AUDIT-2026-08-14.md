## Executive Summary

The documentation is structurally sound and the public-claims discipline (`docs/public-claims.md`, `docs/TEST_COUNT_AUTHORITY.md`) is a genuine strength — most docs correctly frame compliance work as "evidence mapping" rather than certification, and the zero-dependency / version / Alpha claims are accurate. However, **the canonical test-count authority is stale**, which has propagated an obsolete number across the public surface, and **the GitHub org rename (`hummbl-io` → `hummbl-io`) was never propagated** to documentation. These two issues account for the majority of findings.

| Severity | Count |
|----------|-------|
| HIGH | 9 distinct issues (affecting 100+ files) |
| MEDIUM | 8 |
| LOW | 3 |

**Top 3 fixes by impact:**
1. Update the stale test count (2081 → 2239) in `TEST_COUNT_AUTHORITY.md`, `public-claims.md`, README, and dependents.
2. Replace `hummbl-io` → `hummbl-io` org references repo-wide (374 matches across docs).
3. Correct the README examples table (lists 25 examples; 18 don't exist) and the "three MCP servers" claim (there are 7).

### M1. `CHANGELOG.md` "25 primitives" / "25 Usage Examples" (lines 92-94)

These appear in a historical v1.0.0 release entry. At v1.0.0 the primitive count may genuinely have been 25, so this is likely **historically accurate**. `gov.record_usage(provider="anthropic", model="claude-4", ...)` — cosmetic, not a falsifiable package claim, but may read as dated. Low priority.

### M3. `docs/integrations/README.md` lists only 5 of 10 examples (lines 28-32)

Lists the 5 integration examples but omits the 5 governance examples (`agent_runner`, `circuit_breaker_wrap`, `delegate_task`, `failure_injection`, `kill_switch_modes`). Inverse of H3's problem.

### M4. `docs/ecosystem/PLAN.md` stale milestone (line 103)

"2026-05-15 | krineia v1.0 | ... | ❌ MISSED" — a dated missed milestone. Legitimately historical, but if the plan is meant to be current it should note the miss was resolved or carried forward.

### M5. `docs/OWASP_MAPPING.md:10` "seven governance primitives"

Says "providing seven governance primitives" in the OWASP-mapping scope. This likely refers to the 7 marketed primitives on hummbl.io (per `public-claims.md` Metric Scope Table), not the 34 implemented. Ambiguous without that context — add a scope clarifier.

### M6. `docs/research/hummbl-primitive-matrix-v0.1.md` and `-expansion-v0.1.md`

Both reference superseded codebase state (e.g. "8 kernel invariants, 5 doctrine invariants" vs current K1-K11, D1-D7). Both *do* carry prominent "historical artifact, superseded by PRIMITIVES.md v1.2.0" warnings — correctly handled. Flagged only so the warnings are not removed in a future cleanup.

### M7. `AUDIT.md` internal inconsistency (lines 3-4 vs 12)

Header says "Current package version is v1.2.2 with 2,027 collected tests" (stale, see H1) while the body's "Test suite: 591 tests" is correctly marked as historical v0.4.0. The header mixes current version with stale count.

### M8. `README.md` architecture badge "Tested on Ubuntu 24.04 · macOS M-series · Windows 11 + WSL2" (line 106)

`AGENTS.md` states CI runs on a **Gitea self-hosted Windows runner (`ci-runner`)**, not GitHub Actions matrix on Ubuntu/macOS/Windows. The "Tested on" badge claims a CI matrix that the repo's own CI config does not support. `public-claims.md:17` claims CI tests "Python 3.11, 3.12, and 3.13" — verify whether that matrix exists in `.gitea/workflows/ci.yml` or only in `.github/workflows/ci.yml` (the repo has both `.gitea` and `.github` dirs). If the OS matrix is aspirational, the badge overclaims.
