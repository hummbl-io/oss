# Improvement Loop

Date: 2026-03-27
Status: draft

## Purpose

Define the operating loop for improving HUMMBL research, schemas, experiments, and implementation surfaces without drifting into idea sprawl.

## Core Rule

Move every promising idea through the same sequence:

1. claim
2. structure
3. evidence
4. comparison
5. revision

If an idea stays in prose too long, it is probably not improving.

## The Loop

### 1. Capture

Turn the idea into a named artifact immediately.

Examples:

- note
- memo
- taxonomy
- experiment brief
- repo decision

Goal:

- avoid losing shape
- avoid repeating the same thought in chat

### 2. Formalize

Ask what the idea requires to stop being just narrative.

Possible next forms:

- schema
- example fixture
- benchmark contract
- case-log template
- protocol

Goal:

- make the idea executable or inspectable

### 3. Test

Collect one of:

- source evidence
- artifact evidence
- empirical evidence
- negative evidence

Goal:

- get contact with reality quickly

### 4. Compare

Ask:

- compared to what baseline?
- compared to what human process?
- compared to what adjacent method?

Goal:

- prevent isolated elegance

### 5. Revise

Update:

- the claim
- the spec
- the schema
- the example
- the experiment

Goal:

- reduce drift
- keep the corpus coherent

## Working Heuristics

- if a claim has no falsifier, it is not ready
- if a schema has no example, it is not ready
- if an experiment has no negative case, it is not ready
- if a framework term is not connected to evidence, it is not ready
- if an implementation surface has no benchmark plan, it is not ready

## Best Current Improvement Targets

1. run real case logs
2. build gold sets
3. compare regimes, not just ideas
4. capture failures early
5. keep the terminology stable enough for others to build on

## Anti-Patterns

- endless literature ingestion without synthesis
- proliferating terms without schemas or examples
- implementation without benchmark discipline
- novelty claims without nearest-neighbor comparison
- positive-result bias

## Bottom Line

Improvement means converting intuition into structure, then structure into evidence, then evidence into revision.
