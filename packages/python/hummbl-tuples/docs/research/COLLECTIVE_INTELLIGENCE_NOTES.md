# Collective Intelligence Notes

Date: 2026-03-27
Status: draft

## Question

What does collective intelligence add to HUMMBL?

## Bottom Line

Collective intelligence gives HUMMBL a way to think about reasoning as something distributed across groups, tools, and institutions rather than residing in a single agent. It is the clearest domain for asking when aggregation, diversity, memory, and coordination improve decision quality.

For HUMMBL, this matters because the target system is not just one model. It is a sociotechnical reasoning network of humans, agents, artifacts, and governance mechanisms.

## Core Ideas

- groups can outperform individuals under the right coordination conditions
- diversity, independence, and aggregation quality all matter
- shared memory and external artifacts are part of collective cognition
- coordination failures can destroy otherwise strong group intelligence
- collective intelligence depends on protocols, not only participant quality

## What HUMMBL Should Borrow

- design explicit aggregation and coordination protocols
- preserve diversity of reasoning paths instead of collapsing too early
- use tuples as shared memory and comparison artifacts
- measure group-level performance, not only single-agent quality
- treat human-agent teams as collective-intelligence systems

## What HUMMBL Should Avoid

- assuming more participants automatically means better reasoning
- over-centralizing judgment and losing diversity
- treating shared memory as a byproduct instead of an asset
- confusing consensus with quality
- evaluating only single-turn or single-agent outputs
